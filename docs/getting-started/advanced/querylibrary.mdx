# Optional Command Parameter Library 🧩

This page is a deep reference for players who want precise control over commands. The bot supports several parameter styles across card, claim, collection, and effect commands — and once you learn the patterns, you can slice, sort, and filter your way to exactly the cards you're looking for.

:::note
Not every command uses every parameter. Many of these options show up most often in card-related flows like `/cards`, `/claim cards`, `/summon`, `/eval`, and collection commands.
:::

---

## Card Query (`card_query`) — the heart of card commands

The `card_query` parameter is the single most powerful tool in the bot. You feed it a string of keywords, filters, and sorters, and the bot parses them all at once. You can combine as many as you want in a single query.

**Basic keyword search** — just type a name or partial name:

| Command | What it does |
| --- | --- |
| `/cards card_query:twice` | Search cards by collection/name |
| `/cards card_query:mo` | Partial name matches work too |
| `/summon card_query:chaeyoung` | Summon a specific card by name |

The bot matches card **names** using regex, so partial matches work fine. You don't need to type the full name.

:::tip
If you want to search for a card by its **ID** rather than name, the bot also auto-completes IDs in Discord's parameter dropdown!
:::

## Filtering syntax (`-` and `!`)

This is the core of advanced queries. Prefix a filter with **`-`** to include or **`!`** to exclude. The parser treats every space-separated word that starts with `-` or `!` as a filter.

### By collection

| Command | What it does |
| --- | --- |
| `/cards card_query:-twice` | Show only cards from the `twice` collection |
| `/cards card_query:-ive` | Show only cards from the `ive` collection |
| `/cards card_query:!blackpink` | Exclude all `blackpink` cards |

- **`-collection`** — show only cards from that collection
- **`!collection`** — exclude all cards from that collection

The bot auto-matches collection names, so you can use partial names. For example `-twice` matches the `twice` collection.

### By star level (rarity)

| Command | What it does |
| --- | --- |
| `/cards card_query:-3` | Show only 3★ cards |
| `/cards card_query:-1 -2` | Show only 1★ and 2★ cards |
| `/cards card_query:!4` | Exclude all 4★ cards |
| `/cards card_query:!1 !2` | Exclude 1★ and 2★ cards |

- **`-1`**, **`-2`**, **`-3`**, **`-4`**, **`-5`** — show only cards of that star level
- **`!1`**, **`!2`**, **`!3`**, **`!4`** — exclude cards of that star level

These are numeric filters on the card's `level` (star rating), not the card's name.

### By card type / promo status

| Command | What it does |
| --- | --- |
| `/cards card_query:-promo` | Show only promo-type cards |
| `/cards card_query:!promo` | Exclude promo cards (show only normal) |
| `/cards card_query:-limited` | Show only limited cards |
| `/cards card_query:!liveauction` | Exclude live auction cards |
| `/cards card_query:-lottery` | Show only lottery cards |
| `/cards card_query:!lottery` | Exclude lottery cards |

The bot checks if the card's collection is promo/limited/liveauction/lottery/etc. and filters accordingly.

### By card state (inventory only)

These filters only work when querying **your own card inventory** (not global):

| Command | What it does |
| --- | --- |
| `/cards card_query:-fav` | Only favorited cards |
| `/cards card_query:!fav` | Only non-favorited cards |
| `/cards card_query:-lock` | Only locked cards |
| `/cards card_query:!lock` | Only unlocked cards |
| `/cards card_query:-new` | Cards obtained since your last `/daily` |
| `/cards card_query:!new` | Cards obtained before your last `/daily` |
| `/cards card_query:-rated` | Cards you have rated |
| `/cards card_query:!rated` | Cards you haven't rated |
| `/cards card_query:-wish` | Cards on your wishlist |
| `/cards card_query:!wish` | Cards not on your wishlist |
| `/cards card_query:-multi` | Cards you own more than 1 of |
| `/cards card_query:!multi` | Cards you own exactly 1 of |

### By animation

| Command | What it does |
| --- | --- |
| `/cards card_query:-gif` | Animated cards only |
| `/cards card_query:!gif` | Static (non-animated) cards only |

### By group type

| Command | What it does |
| --- | --- |
| `/cards card_query:-girlgroups` | Girls groups only |
| `/cards card_query:-boygroups` | Boy groups only |

:::note
Soloists are usually treated by their assigned gender group rather than having their own category.
:::

### With fragments

| Command | What it does |
| --- | --- |
| `/cards card_query:-fragments` | Only fragment collection cards |

### Recipe cards

| Command | What it does |
| --- | --- |
| `/cards card_query:-recipe` | Cards assigned to an active recipe in your inventory |
| `/cards card_query:!recipe` | Exclude recipe-assigned cards |

## Sorting with `>` and `<`

You can sort the results by prepending `>` (descending) or `<` (ascending) to a sort key.

| Command | Sort direction |
| --- | --- |
| `/cards card_query:>name` | Alphabetical A→Z |
| `/cards card_query:<name` | Reverse alphabetical Z→A |
| `/cards card_query:>star` | Highest star level first |
| `/cards card_query:<star` | Lowest star level first |
| `/cards card_query:>eval` | Most valuable (Flakes Cost) first |
| `/cards card_query:<eval` | Least valuable (Flakes Cost) first |
| `/cards card_query:>date` | Newest first (by obtained date) |
| `/cards card_query:<date` | Oldest first |
| `/cards card_query:>rating` | Highest rated first |
| `/cards card_query:<rating` | Lowest rated first |
| `/cards card_query:>levels` | Highest XP/level first |
| `/cards card_query:<levels` | Lowest XP/level first |
| `/cards card_query:>col` | Alphabetical by collection name |
| `/cards card_query:<col` | Reverse alphabetical by collection name |
| `/cards card_query:>amount` | Most copies first |
| `/cards card_query:<amount` | Fewest copies first |

If no sort is given, the default order is **star level descending → collection → name**.

:::tip
You can chain sorts! For example, `>col <star` sorts by collection A→Z, then by star level ascending within each collection.
:::

### Amount filters

| Command | What it does |
| --- | --- |
| `/cards card_query:>2` | Cards where you own **more than 2** copies |
| `/cards card_query:<5` | Cards where you own **fewer than 5** copies |
| `/cards card_query:=1` | Cards you own **exactly 1** copy of |
| `/cards card_query:>=3` | Cards where you own **3 or more** copies |

These are numeric comparisons on the `amount` property. Works in your personal inventory only.

## Special symbols

### `.` — last viewed card

| Command | What it does |
| --- | --- |
| `/summon card_query:.` | Summon the last card you viewed |
| `/info card_query:.` | Show info on the last card you viewed |

The dot `.` references the **last card you viewed or interacted with**. The bot stores this per-user, so you can quickly pull up the same card again without re-typing the name.

### `#tag` — filter by user-created tags

| Command | What it does |
| --- | --- |
| `/cards card_query:#cute` | Show cards tagged with `cute` |
| `/cards card_query:#rare !#common` | Show cards tagged `rare` but not `common` |

Tags are user-submitted labels on cards (managed via `/tag` commands). You can filter for cards that have (or don't have) specific tags.

- **`#tag`** — show cards with this tag
- **`!#tag`** — exclude cards with this tag

### `:extra` — command-specific extra data

| Command | What it does |
| --- | --- |
| `/effect use effect_name:judgeday extra_arguments:claimrecall` | Use Judgment Day to copy Claim Recall |
| `/effect use effect_name:spaceunity extra_arguments:-ive` | Use Space Unity to target the `ive` collection |

The colon `:` prefix passes extra arguments that some commands interpret differently. For instance, with **The Judgment Day** effect, everything after the effect name in `extra_arguments` is forwarded to the copied effect.

### `$source` — filter by image source

| Command | What it does |
| --- | --- |
| `/cards card_query:$booru` | Show cards with image sourced from booru |

Filters cards whose metadata has a matching source tag. This is a niche filter used alongside `/meta` commands for source tracking.

## Command-specific optional parameters

Beyond the card query syntax, many commands have their own dedicated optional parameters. Here's the full list grouped by command.

### `/claim cards` and `/level claim`

| Parameter | Type | What it does |
| --- | --- | --- |
| `count` | Number | How many cards to claim at once (e.g., `count:5`) |
| `promo` | Boolean | Claim using promo currency instead of flakes |
| `any` | Boolean | Skip the autocomplete step and claim any random card |
| `boost_id` | String | Target a specific active event/boost (e.g., `boost_id:christmas25`) |
| `group_type` | String | Restrict to a group category (e.g., `girlsgroups`, `boygroups`) |
| `unlocked` | Boolean | Only claim from unlocked collections |

### `/cards`

| Parameter | Type | What it does |
| --- | --- | --- |
| `card_query` | String | Your inventory cards matching this query |
| `global` | Boolean | If `true`, search the global card pool instead of your inventory |

### `/sell`

| Parameter | Type | What it does |
| --- | --- | --- |
| `card_query` | String | Card(s) to sell |
| `price` | Number | Optional — set a custom price for `/sell one` |
| `count` | Number | Optional — how many to sell for `/sell many` |

### `/eval`

| Parameter | Type | What it does |
| --- | --- | --- |
| `card_query` | String | Card(s) to evaluate |
| `count` | Number | How many cards to eval at once |
| `global` | Boolean | Evaluate from the global card pool instead of your inventory |

### `/fav`, `/rate`, `/wish`, `/lock`

| Parameter | Type | What it does |
| --- | --- | --- |
| `card_query` | String | Card(s) to target |
| `count` | Number | How many cards to process at once |
| *(subcommand)* | String | `one`, `many`, `remove one`, `remove many`, or `list` |

### `/forge`, `/ascend`, `/combine`

| Parameter | Type | What it does |
| --- | --- | --- |
| `card_query_1` | String | First card to use |
| `card_query_2` | String | Second card to use |

Both queries use the full card query syntax, so you can use filters, sorts, and keywords for each slot.

### `/liquefy`

| Parameter | Type | What it does |

### `/draw`

## Quick reference: card query syntax summary

| Syntax | What it does | Example |
| --- | --- | --- |
| `text` | Search card names | `twice` |
| `.` | Last viewed card | `.` |
| `-collection` | Include collection | `-twice` |
| `!collection` | Exclude collection | `!blackpink` |
| `-N` | Include star level N | `-3` |
| `!N` | Exclude star level N | `!1` |
| `-promo` | Promo cards only | `-promo` |
| `!promo` | Non-promo only | `!promo` |
| `-limited` | Limited cards only | `-limited` |
| `-fav` / `!fav` | Favorited / not favorited | `-fav` |
| `-lock` / `!lock` | Locked / unlocked | `-lock` |
| `-new` / `!new` | Obtained since daily / before | `-new` |
| `-rated` / `!rated` | Rated / unrated | `-rated` |
| `-wish` / `!wish` | Wishlisted / not | `-wish` |
| `-multi` / `!multi` | Duplicates / singles | `-multi` |
| `-gif` / `!gif` | Animated / static | `-gif` |
| `-girlgroups` / `-boygroups` | Group type | `-girlgroups` |
| `-fragments` | Fragment collections | `-fragments` |
| `-recipe` / `!recipe` | Recipe-assigned cards | `-recipe` |
| `-diff` / `!diff` | Diff mode | `-diff` |
| `>key` | Sort descending | `>eval` |
| `<key` | Sort ascending | `<name` |
| `>N` | Amount > N | `>2` |
| `<N` | Amount < N | `<5` |
| `=N` | Amount = N | `=1` |
| `>=N` | Amount >= N | `>=3` |
| `#tag` | Has tag | `#cute` |
| `!#tag` | Doesn't have tag | `!#common` |
| `:data` | Extra argument | `:claimrecall` |
| `$source` | Source filter | `$booru` |

## Quick reminder

If you're still getting comfortable with commands, the best approach is to start simple and let autocomplete help you. The advanced parameter syntax becomes much easier once you already know the basic command names and the kinds of cards you're trying to target. Feel free to bookmark this page and come back as you level up — there's always a new filter to try! 🚀
